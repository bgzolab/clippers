## 为什么 Linux 要用 tar.gz，很少用 7Z 或 ZIP？

作为一个从机械转行做了快10年嵌入式的老码农，这个问题我太有发言权了。

当年刚进某马做单片机开发的时候，我也纳闷过这事儿。后来在外企做 Linux 应用开发，天天跟 tar.gz 打交道，才算真正理解了这背后的门道。

### 这事儿得从 Unix 的哲学讲起

Linux 继承了 Unix 的一个核心思想——**一个工具只干一件事，但要干到极致** 。

tar 是什么？打包工具，把一堆文件打成一个包，但它不压缩。

gzip 是什么？压缩工具，专门负责压缩，但它只能压缩单个文件。

两个工具配合，就是 tar.gz。这就是典型的 Unix 哲学：模块化、可组合。

你看 Windows 那套，ZIP 既打包又压缩，看起来很方便对吧？但在 Linux 世界里，这叫**耦合度太高**
。我想只打包不压缩怎么办？我想换个压缩算法怎么办？

这就是为什么你会看到 tar.bz2、tar.xz、tar.zst 这些变种——tar
负责打包，后面的压缩算法随便换。这种设计在做嵌入式产品的时候特别有用，不同的硬件平台对压缩算法的支持不一样，灵活性就体现出来了。

### 历史包袱这个东西，真的很重

Linux 诞生于 1991 年，那时候 tar 和 gzip 已经在 Unix 世界用了十几年了。整个生态都是围绕这套工具链建立的。

你让所有的脚本、所有的构建系统、所有的包管理器都改成 7z？这工作量不亚于重构一个操作系统。

我在外企做汽车电子的时候，见过一个项目用了 20 年前的构建脚本，里面全是 tar、gzip 的命令。你说要改成
7z？产品经理第一个不答应——**改动越大，风险越高** ，这是做工程的铁律。

而且说实话，7z 虽然压缩率高，但它是 1999 年才出现的，比 gzip 晚了快 10 年。等它想进入 Linux
生态的时候，人家的护城河已经挖得够深了。

### 开源协议这个坑，很多人不知道

gzip 用的是 GNU GPL 协议，完全开源，没有任何专利问题。

ZIP 呢？早期有专利纠纷，虽然现在解决了，但在开源社区留下了心理阴影。

7z 倒是开源的，用的是 LGPL 协议，但它的生态主要在 Windows。Linux
社区对它的接受度一直不高，有点像你去东北烧烤摊点了份广式早茶，老板虽然能做，但总觉得哪里不对味儿。

我做自媒体这几年，写过不少 Linux 相关的文章，每次提到压缩格式，评论区总有人问“为啥不用 7z”。其实不是技术问题，是**路径依赖** 问题。

### 性能这个事儿，得看场景

很多人觉得 7z 压缩率高就是好，但在服务器环境下，**解压速度** 往往比压缩率更重要。

gzip 解压快，CPU 占用低，这在处理日志文件、部署代码的时候非常关键。你想想，一个 CI/CD
流水线每天要跑几百次构建，每次都要解压代码包，差个几秒钟累积下来就是几分钟。

我之前在公司做嵌入式 Linux 应用开发的时候，经常要在开发板上解压文件系统。那些 ARM 芯片的性能本来就不强，用 7z 解压能把 CPU
跑满，gzip 就轻松多了。

而且 tar.gz 是**流式处理** 的，可以边下载边解压，这在网络传输的时候优势明显。7z 必须下载完整个文件才能解压，这在带宽受限的环境下就是硬伤。

### 生态位这个东西，一旦形成就很难打破

Linux 的包管理器，不管是 apt、yum 还是 pacman，默认都支持 tar.gz。你要用 7z？得自己装工具，自己写脚本。

内核源码？tar.gz。各种开源项目的发布包？tar.gz。Docker 镜像的底层？还是 tar。

这就是**网络效应** ，所有人都用，你不用反而麻烦。就像打工人都用钉钉打卡，你非要用企业微信，HR 第一个找你谈话。

我现在自己创业做技术咨询，给客户做嵌入式方案的时候，从来不会建议他们用 7z 或 ZIP。不是这些格式不好，而是用 tar.gz
能减少太多不必要的麻烦——工具链成熟、文档齐全、出了问题网上一搜一大把解决方案。

### 说到底，这是个工程问题，不是技术问题

技术上 7z 确实更先进，压缩率更高，支持的算法更多。但工程上，tar.gz 的优势在于：

  * 工具链成熟，到处都有
  * 性能够用，解压快
  * 生态完善，所有人都支持
  * 历史悠久，没有兼容性问题

做技术这么多年，我最大的感悟就是：**能用的技术才是好技术，不是最新的技术才是好技术** 。

就像我当年从机械转嵌入式，一开始也想着要用最新的框架、最炫的工具。后来发现，能按时交付、稳定运行的项目，用的都是那些“老掉牙”的技术栈。

tar.gz 就是这样一个“老掉牙”但好用的东西。它可能不是最优解，但绝对是最稳妥的选择。

## 嵌入式学习路线完整指南

既然聊到 Linux 和嵌入式，我就把这些年摸爬滚打总结的学习路线分享给你。

### 学习大纲

![](https://pic1.zhimg.com/50/v2-18165d96594693ac1a024ef3b8c14bda_720w.jpg?source=2c26e567)

### 详细学习大纲

### 第一阶段：打好基础（1-3个月）

**C语言必须吃透**

很多人觉得 C 语言简单，学几天就开始写项目了。但嵌入式开发对 C 的要求远比应用开发高。

指针这块必须理解到骨子里。什么是指针的指针？函数指针怎么用？指针数组和数组指针有什么区别？这些不是背概念，而是要在实际代码里反复练习。我当年刚做单片机的时候，被指针折磨了好几个月，后来发现问题在于没有理解内存模型。你得知道变量在内存里是怎么存的，指针只是一个地址，通过地址去访问内存里的数据。

位操作在嵌入式里用得特别多。寄存器配置基本都是位操作，比如设置某个引脚为输出模式，你得把对应寄存器的某几位置
1。左移右移、与或非、异或，这些操作要熟练到不假思索。还有结构体的位域，在处理硬件寄存器的时候特别好用。

内存管理也很关键。嵌入式系统内存有限，动态分配要慎用。什么时候用栈，什么时候用堆，内存对齐是怎么回事，内存泄漏怎么排查，这些都得清楚。

**数据结构不能只停留在理论**

链表在嵌入式里用得最多，内核里到处都是链表。单链表、双向链表、循环链表，不光要会写，还要知道什么场景用什么链表。队列在 RTOS
里是核心数据结构，任务间通信基本都靠队列。栈在函数调用、中断处理里都有体现。

排序算法不用全学，但快排、冒泡、插入排序得会。查找算法里二分查找很常用，哈希表在做数据缓存的时候能派上用场。

重点是要理解时间复杂度和空间复杂度。嵌入式系统资源受限，你写的算法不能太消耗资源。有时候为了省内存，宁可牺牲一点时间；有时候为了实时性，得用空间换时间。这种权衡能力需要在实践中培养。

**计算机组成原理决定了你的上限**

很多人觉得这门课没用，但在嵌入式开发里，不懂硬件就是寸步难行。

CPU 是怎么执行指令的？取指、译码、执行、访存、写回，这个流程要清楚。流水线、缓存、分支预测这些概念，在做性能优化的时候都会用到。

内存层次结构要理解。寄存器、Cache、内存、外存，访问速度差了好几个数量级。为什么要做内存对齐？为什么局部变量比全局变量快？为什么数组遍历比链表遍历快？都跟内存访问有关。

中断机制是嵌入式的核心。什么是中断向量表？中断优先级怎么设置？中断嵌套是怎么回事？中断里能做什么不能做什么？这些问题在写驱动的时候天天遇到。

### 第二阶段：单片机实战（3-6个月）

**从 51 单片机开始没毛病**

虽然 51 单片机很老，但它结构简单，特别适合入门。GPIO、定时器、串口、中断，这些基本外设在 51 上都能学到。

GPIO 控制看起来简单，就是高低电平，但要理解上拉、下拉、开漏、推挽这些模式。LED 闪烁、按键检测、数码管显示，这些小项目能让你快速上手。

定时器是单片机的核心外设。怎么配置定时时间？怎么在定时器中断里处理任务？怎么用定时器做 PWM 输出？这些都要自己动手实现。

串口通信是单片机和外界交互的主要方式。串口的波特率、数据位、停止位、校验位都是什么意思？怎么发送一个字符？怎么接收一串数据？怎么处理数据帧？这些问题解决了，后面学其他通信协议就容易了。

**STM32 是进阶的最佳选择**

STM32 是目前最流行的 ARM 单片机，生态完善，资料丰富。从 51 到 STM32，你会发现复杂度上升了一个台阶。

HAL 库和寄存器开发要都会。HAL 库开发快，但效率低；寄存器开发麻烦，但效率高。实际项目里往往是混用，关键部分用寄存器，非关键部分用 HAL 库。

DMA 是个好东西，能大幅减轻 CPU 负担。串口接收用 DMA，ADC 采集用 DMA，SPI 传输用 DMA，学会了 DMA，你的代码效率能提升一大截。

SPI、I2C、UART 这些通信接口要吃透。时序图要会看，协议细节要清楚。为什么 SPI 比 I2C 快？为什么 I2C
只需要两根线？这些问题搞明白了，调试外设就不会一头雾水。

**RTOS 是必须要学的**

裸机开发写到一定程度就会遇到瓶颈，任务多了就管不过来。这时候就需要 RTOS。

FreeRTOS 是最流行的开源
RTOS，资料多，社区活跃。任务创建、任务调度、任务同步、任务通信，这些概念要理解。信号量、互斥量、消息队列、事件组，这些机制要会用。

移植 FreeRTOS 到 STM32 是个很好的练习。你会理解什么是任务栈，什么是系统节拍，什么是上下文切换。这些底层机制搞懂了，后面学 Linux
也会轻松很多。

**项目实战才是检验标准**

智能小车是经典项目。电机驱动、超声波避障、循迹、蓝牙遥控，涉及的知识点很全面。做完这个项目，你对单片机的理解会上一个台阶。

环境监测系统也不错。温湿度传感器、光照传感器、烟雾传感器，数据采集、数据处理、数据上传，整个流程走一遍，你就知道物联网设备是怎么工作的了。

无线通信模块比如 ESP8266、NRF24L01，学会了就能做远程控制。把单片机接入互联网，实现手机 APP 控制，这种成就感是看书学不来的。

### 第三阶段：Linux 系统基础（2-3个月）

**Linux 使用是基本功**

命令行要熟练。cd、ls、cp、mv、rm 这些基础命令就不说了，grep、awk、sed
这些文本处理工具要会用。管道、重定向、通配符，这些特性能大幅提高效率。

Shell 脚本要会写。变量、条件判断、循环、函数，这些语法要掌握。写一个自动化编译脚本，写一个批量处理文件的脚本，这些都是实际工作中常用的。

文件系统和权限要理解。什么是 inode？软链接和硬链接有什么区别？rwx 权限是什么意思？chmod、chown
怎么用？这些搞不清楚，后面做根文件系统就会踩坑。

进程管理要清楚。ps、top、kill 这些命令要会用。什么是进程？什么是线程？什么是守护进程？进程的状态有哪些？这些概念在写应用程序的时候都会用到。

**Linux 编程是核心能力**

系统调用是 Linux 编程的基础。open、read、write、close，这些函数看起来简单，但要理解文件描述符、阻塞非阻塞、同步异步这些概念。

进程和线程要分清楚。fork 创建进程，pthread_create
创建线程。进程间独立，线程间共享内存。什么时候用进程，什么时候用线程，要根据实际需求来定。

进程间通信有很多种方式。管道、消息队列、共享内存、信号量、信号，每种方式都有适用场景。管道适合父子进程通信，共享内存速度最快但要处理同步问题，消息队列适合异步通信。

网络编程是应用开发的重点。Socket 编程要会，TCP 和 UDP 的区别要清楚。怎么创建服务器？怎么处理多客户端连接？select、poll、epoll
这些 IO 多路复用机制要理解。

**开发工具链要熟练**

GCC 编译器的参数要知道。-O2 优化、-g 调试信息、-Wall 警告、-I 头文件路径、-L 库文件路径，这些常用参数要记住。

Makefile 是必须会的。规则、变量、函数，这些语法要掌握。写一个能自动检测依赖关系的 Makefile，能大幅提高编译效率。CMake
是更高级的构建工具，大型项目基本都用 CMake。

GDB 调试要熟练。打断点、单步执行、查看变量、查看堆栈，这些操作要熟练。段错误怎么定位？内存泄漏怎么排查？core dump
怎么分析？这些技能在实际开发中太重要了。

Git 版本控制是团队协作的基础。add、commit、push、pull、merge，这些命令要会用。分支管理、冲突解决、回退版本，这些操作要熟练。

### 第四阶段：嵌入式 Linux 开发（6-12个月）

**交叉编译环境是第一关**

什么是交叉编译？在 x86 电脑上编译出 ARM 平台的程序，这就是交叉编译。工具链的搭建要会，buildroot 和 crosstool-ng
是常用工具。

交叉编译的时候会遇到很多问题。头文件找不到、库文件链接失败、运行时找不到动态库，这些问题要会排查。理解 sysroot、prefix、host、target
这些概念，能解决大部分问题。

**Bootloader 是系统启动的关键**

U-Boot 是最常用的 Bootloader。它的作用是初始化硬件、加载内核、传递启动参数。

U-Boot 的移植要会。修改配置文件、添加板级支持、配置网络、配置存储设备，这些步骤要熟悉。

启动流程要理解。上电复位、ROM
代码、SPL、U-Boot、内核、根文件系统，整个流程要清楚。每个阶段做了什么事，出问题了怎么定位，这些能力在实际项目中太重要了。

**内核开发是进阶的标志**

内核配置和裁剪要会。make menuconfig 界面要熟悉，哪些模块需要编译进内核，哪些可以编译成模块，要根据实际需求来定。

设备树是 ARM 平台的标准。什么是设备树？为什么要用设备树？设备树的语法怎么写？怎么在驱动里解析设备树？这些问题搞明白了，驱动开发就容易多了。

内核模块开发是理解内核的最好方式。写一个 Hello World 模块，理解 module_init 和 module_exit。写一个带参数的模块，理解
module_param。写一个导出符号的模块，理解 EXPORT_SYMBOL。

**驱动开发是嵌入式 Linux 的核心**

字符设备驱动是最基础的。file_operations 结构体、register_chrdev、cdev 这些接口要熟悉。写一个虚拟字符设备，实现
open、read、write、ioctl，这是驱动开发的入门。

平台设备驱动是 Linux
设备模型的体现。platform_driver、platform_device，驱动和设备的匹配机制要理解。设备树里定义设备，驱动里实现 probe
函数，这种开发模式要熟练。

中断处理在驱动里很常见。request_irq
注册中断，中断处理函数要快速返回，耗时操作要放到下半部。tasklet、工作队列、软中断，这些下半部机制要理解。

内存映射是访问硬件寄存器的方式。ioremap 映射物理地址，readl/writel 访问寄存器，这些操作要熟练。

常见驱动要会写。GPIO 驱动控制引脚，I2C 驱动读写外设，SPI 驱动传输数据，USB 驱动识别设备。每种驱动的框架要理解，接口要熟悉。

**根文件系统是系统的基础**

BusyBox 是嵌入式 Linux 的标配。它把常用的 Linux 命令集成到一个可执行文件里，大小只有几百 KB。怎么配置 BusyBox？怎么编译
BusyBox？怎么制作根文件系统？这些步骤要熟练。

文件系统类型要了解。ext4 适合大容量存储，jffs2 适合 NOR Flash，ubifs 适合 NAND
Flash。不同的存储介质用不同的文件系统，这是基本常识。

系统启动脚本要会写。/etc/inittab、/etc/init.d/rcS，这些脚本决定了系统启动后做什么。挂载文件系统、配置网络、启动服务，这些操作都在启动脚本里完成。

### 第五阶段：应用层开发（3-6个月）

**应用程序开发是最直接的**

多线程编程要熟练。pthread 库的接口要会用，线程的创建、同步、通信要理解。互斥锁、条件变量、读写锁，这些同步机制要会用。

网络应用很常见。写一个 TCP 服务器，写一个 HTTP 客户端，写一个 WebSocket 通信程序，这些项目能让你理解网络编程的精髓。

数据库在嵌入式里也有应用。SQLite 是嵌入式数据库的首选，轻量级、无需服务器、支持 SQL。怎么创建数据库？怎么插入数据？怎么查询数据？这些操作要熟练。

**常用框架能提高开发效率**

Qt 是跨平台的图形界面框架。信号槽机制、控件使用、布局管理，这些基础要掌握。Qt 在嵌入式里用得很多，工业控制、车载终端、医疗设备，很多都用 Qt
做界面。

LVGL 是专门为嵌入式设计的 GUI 库。它对资源要求低，适合小屏幕设备。控件丰富、主题漂亮、移植简单，是做嵌入式 GUI 的好选择。

MQTT 是物联网的标准协议。发布订阅模式、QoS 等级、遗嘱消息，这些概念要理解。用 MQTT
连接云平台，实现设备的远程监控和控制，这是物联网开发的基本技能。

**项目实战是检验能力的标准**

智能家居网关是个综合项目。连接各种传感器和执行器，处理数据，上传云平台，接收控制命令。涉及硬件驱动、网络通信、数据处理、云平台对接，是个很好的练手项目。

工业控制系统对实时性要求高。数据采集、逻辑控制、人机交互，整个流程要稳定可靠。做这种项目能培养你的工程思维，知道什么叫可靠性设计。

车载终端是我在外企做的方向。CAN 总线通信、GPS 定位、4G 联网、OTA
升级，这些功能都要实现。汽车电子对安全性和可靠性要求极高，做这种项目能让你理解什么叫工业级产品。

### 第六阶段：进阶方向（持续学习）

**实时操作系统是深入的方向**

FreeRTOS 的源码要读。任务调度算法、内存管理、时间管理，这些核心模块要理解。看懂了 FreeRTOS 的源码，你对操作系统的理解会上一个台阶。

RT-Thread 是国产 RTOS，生态越来越好。它的组件丰富，文档齐全，社区活跃。学习 RT-Thread 能让你理解国产操作系统是怎么做的。

任务调度和同步是 RTOS
的核心。抢占式调度、时间片轮转、优先级反转，这些问题要理解。怎么设计任务优先级？怎么避免死锁？怎么提高系统的实时性？这些问题在实际项目中经常遇到。

**性能优化是高级能力**

代码优化有很多技巧。减少函数调用、使用内联函数、循环展开、查表法，这些技巧能提高代码效率。但要注意，过度优化会降低代码可读性，要在性能和可维护性之间找平衡。

内存优化在嵌入式里很重要。减少全局变量、复用缓冲区、使用内存池，这些方法能降低内存占用。内存泄漏要及时发现和修复，valgrind 是个好工具。

启动速度优化能提升用户体验。并行启动、延迟加载、裁剪内核，这些方法能缩短启动时间。我在外企做车载终端的时候，客户要求开机 3
秒内显示界面，为了达到这个指标，我们做了大量优化工作。

**安全和可靠性是产品化的关键**

看门狗机制是保证系统稳定的基本手段。硬件看门狗、软件看门狗，要根据实际情况选择。喂狗的时机要合理，不能喂得太频繁，也不能喂得太慢。

异常处理要完善。段错误、总线错误、除零错误，这些异常要能捕获和处理。记录日志、保存现场、自动重启，这些机制能提高系统的可靠性。

安全启动在一些高安全性场景是必须的。验证
Bootloader、验证内核、验证根文件系统，确保系统没有被篡改。加密、签名、安全芯片，这些技术在金融、军工领域用得很多。

**行业应用是职业发展的方向**

汽车电子是个大方向。AUTOSAR 是汽车软件的标准，CAN、LIN、FlexRay 是汽车总线。功能安全（ISO 26262）、信息安全（ISO
21434），这些标准要了解。我在外企做的就是汽车电子，这个领域技术门槛高，但薪资也高。

工业控制也是个大方向。PLC
编程、现场总线（Profibus、Modbus）、工业以太网，这些技术要掌握。工业控制对实时性和可靠性要求极高，是锻炼技术能力的好领域。

物联网是未来的趋势。传感器、通信模块、云平台、大数据，整个生态链很长。做物联网需要全栈能力，从硬件到软件，从设备到云端，都要懂一点。

### 学习建议

从机械转行嵌入式这条路，我走了快10年。这些年的经验告诉我，学习嵌入式不是一蹴而就的事，需要耐心和坚持。

**别着急，一步一步来**

很多人刚开始学就想做大项目，结果基础没打牢，后面越学越吃力。我当年在某马做单片机的时候，就是因为C语言基础不扎实，调试一个指针问题能卡一整天。后来痛定思痛，花了两个月重新把C语言和数据结构过了一遍，才算真正入门。

基础知识一定要扎实。C语言、数据结构、操作系统，这些看起来枯燥，但都是内功。内功不够，招式再花哨也没用。

**动手实践比看书重要**

嵌入式是个实践性很强的领域，光看书是学不会的。买块开发板，把书上的例程都跑一遍，自己改改代码，看看效果。遇到问题就去调试，去查资料，去问人。这个过程虽然痛苦，但成长最快。

我在外企做Linux应用开发的时候，有个同事特别喜欢看书，各种经典教材都看过，但一写代码就出问题。后来发现他只看不练，理论和实践脱节了。嵌入式开发不是纸上谈兵，得真刀真枪地干。

**项目驱动学习最有效**

给自己定个小目标，比如做个智能小车，做个环境监测系统。为了完成这个项目，你会主动去学相关的知识。这种目标驱动的学习方式，比漫无目的地看书效率高多了。

我28岁开始写公众号的时候，为了写好文章，逼着自己去深入研究各种技术细节。这个过程让我对很多知识点的理解更深入了。所以，找个能激励你的目标，学习就不会那么枯燥了。

**加入社区，多交流**

嵌入式的坑很多，一个人闷头学很容易走弯路。加入一些技术社区，比如CSDN、博客园、知乎，看看别人是怎么学的，遇到问题怎么解决的。

GitHub上有很多优质的开源项目，多看看别人的代码，学习别人的编程思想和代码风格。看懂了别人的代码，自己写起来就有思路了。

我做自媒体这几年，认识了很多同行，大家经常交流技术问题，互相帮助。这种交流让我学到了很多书本上学不到的东西。

**持续学习，保持好奇心**

技术更新很快，今天学的东西，明天可能就过时了。保持学习的习惯，关注行业动态，了解新技术。

但也不要盲目追新，不是所有新技术都值得学。要根据自己的职业规划，选择性地学习。比如你想做汽车电子，那AUTOSAR、CAN总线这些就是重点；你想做物联网，那MQTT、LoRa这些就要掌握。

我现在创业做技术咨询，经常要接触不同的行业和技术。这种跨界的经历让我意识到，学习能力比具体的技术更重要。只要学习能力强，任何新技术都能快速上手。

**找个好的导师或团队**

如果能找到一个经验丰富的导师，或者加入一个技术氛围好的团队，你的成长速度会快很多。导师能帮你少走弯路，团队能给你提供实践机会。

我在外企的那几年，跟着一个技术大牛学了很多东西。他不光教我技术，还教我怎么思考问题，怎么设计系统。这种言传身教的效果，是看书学不来的。

如果找不到导师，那就多看看大牛的博客和文章，学习他们的思维方式。慢慢地，你也会形成自己的技术体系。

**不要怕犯错，错误是最好的老师**

写代码肯定会出bug，调试硬件肯定会烧板子。这些都是正常的，不要因为害怕犯错就不敢动手。

我刚做嵌入式的时候，烧坏过好几块开发板，写的代码也经常跑飞。但每次出问题，我都会认真分析原因，下次就不会再犯同样的错误。这种试错的过程，虽然代价高，但学到的东西最深刻。

**平衡工作和学习**

如果你已经工作了，那就要平衡好工作和学习的关系。工作是学习的最好场景，工作中遇到的问题就是学习的方向。

我在外企工作的时候，白天写代码，晚上看书学习。周末的时候做点自己的小项目，巩固学到的知识。这种工作学习两不误的状态，让我成长很快。

后来开始做自媒体，边工作边创业，时间更紧张了。但我还是坚持每天学习，哪怕只有半小时。积少成多，几年下来，积累了很多东西。

**保持身体健康**

程序员是个高强度的职业，经常加班熬夜。但身体是革命的本钱，没有好身体，再多的技术也施展不出来。

我现在每周都会运动几次，跑步、健身、打球。运动不光能保持身体健康，还能缓解压力，提高工作效率。

所以，学习嵌入式的同时，别忘了照顾好自己的身体。

* * *

最后说一句，嵌入式这条路不好走，但只要坚持下来，回报是很丰厚的。
