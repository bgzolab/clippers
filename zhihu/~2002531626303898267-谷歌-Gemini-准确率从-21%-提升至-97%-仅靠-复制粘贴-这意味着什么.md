我了个手动注意力机制，人类的本质是复读机。

  1. 重要的话说三遍，复读 is all u need！
  2. 重要的话说三遍，复读 is all u need！
  3. 重要的话说三遍，复读 is all u need！

* * *

仔细推导了一下，其实原版 Attention 机制是不会出现这种问题的。

这个其实是 Causal LM 才会有的问题，这个技巧本质上是在用 Causal LM 模拟蹩脚的 Prefix LM。

根据原始的《Attention Is All You Need》，在正宗老北京风味的 Transformer 架构里，模型需要由一个 Encoder
和一个Decoder 组成。

完整的注意力矩阵是一个方阵，这时的自注意力机制是 Bidirectional 的，计算任何一个词的表征时，模型都可以同时看到这个词之前和之后的所有词。

这种情况下根本不会出现读到后面忘了前面，或者只读前面不知道后面要考什么的老年痴呆现象。

* * *

但是 GPT、LLaMA、Gemini 这些模型全都偷懒了，扔掉了 Encoder，采用了所谓的 Decoder-Only 架构。

此时 Decoder 的任务就变成了 Generation，以 Autoregressive 的方式，逐个生成文本。

为了做到这一点，模型在预测第 ![i](https://www.zhihu.com/equation?tex=i) 个词时，只能看到它前面已经生成的
![i-1](https://www.zhihu.com/equation?tex=i-1) 个词，绝不能偷看第
![i](https://www.zhihu.com/equation?tex=i) 个词及其之后的内容。

这就是最主流的因果语言模型（Causal Language Model, Causal LM）。

* * *

为了在技术上实现这种限制，解码器的自注意力机制引入了 Attention Mask。

Causal LM 大概切掉了一半的脑组织，此时的注意力掩码是一种下三角矩阵。

在计算注意力权重时，这个掩码会强制将注意力矩阵中代表未来的上三角部分权重设置为一个极大的负数，这样经过
![\\text{softmax}](https://www.zhihu.com/equation?tex=%5Ctext%7Bsoftmax%7D)
函数后，这些位置的权重就变成了 ![0](https://www.zhihu.com/equation?tex=0)。

这样一来，当模型处理序列中的第 ![i](https://www.zhihu.com/equation?tex=i) 个词时，它就只能关注从第
![0](https://www.zhihu.com/equation?tex=0) 个到第
![i](https://www.zhihu.com/equation?tex=i) 个词的所有信息，但对于第
![i+1](https://www.zhihu.com/equation?tex=i%2B1) 个词及之后的所有内容，一无所知。

这里的工程优势就是训练简单，模型只需要预测下一个词的目标函数，就可以在海量的文本数据上进行预训练。

* * *

但是这里就挖了个坑。

假设我们的输入是【上下文 C + 问题 Q】，当模型从左到右处理 C 部分的 Token 时，由于因果掩码的存在，它对后面即将出现的 Q 毫无觉察。

它只能基于 C 本身的内容去构建每个 Token 的 KV 对，并将它们存入所谓的 KV 缓存中。

然而这些在无知状态下生成的 KV 对，其特征表示是未经问题引导的，是泛化的。

当模型终于处理到 Q 部分时，它会视图用 Q 生成的查询向量去检索 C 部分的 KV 缓存。

但此时就会尴尬的发现，由于 C 在编码时并不知道 Q 的意图，导致其生成的 KV 对与 Q
的查询向量匹配度不高，关键信息在多层神经网络的传递中已经被稀释掉了。

**好家伙，考试阅读理解，问题都不给先读一遍，读完收走再告诉我题目，这也能考高分也是神人了。**

* * *

那么为啥复制粘贴有效呢？

这其实可以理解为一种手工特征工程，视图在 Causal LM 的架构限制下，强行模拟出类似 Prefix LM 的双向信息流效果。

加入现在复读了一遍，输入变成了 `C + Q + C + Q`。

第一遍处理 `C + Q`，模型处理第一段上下文 ![C_1](https://www.zhihu.com/equation?tex=C_1)
时，它仍然处于因果盲区中，不知道后面的问题 ![Q_1](https://www.zhihu.com/equation?tex=Q_1)，它生成的
![C_1](https://www.zhihu.com/equation?tex=C_1) 的 KV 缓存是无知的。

当处理到 ![Q_1](https://www.zhihu.com/equation?tex=Q_1) 时，它开始利用
![Q_1](https://www.zhihu.com/equation?tex=Q_1) 的信息，但为时已晚，无法回头修正
![C_1](https://www.zhihu.com/equation?tex=C_1) 的表征。

当模型开始处理第二段上下文 ![C_2](https://www.zhihu.com/equation?tex=C_2) 时就不一样了，由于
![C_2](https://www.zhihu.com/equation?tex=C_2) 的每个词元在序列中的位置都位于第一遍的 `C + Q`
之后，根据因果注意力的规则，它们现在可以无障碍地看到 ![C_1](https://www.zhihu.com/equation?tex=C_1) 和
![Q_1](https://www.zhihu.com/equation?tex=Q_1) 的所有信息。

在处理 ![C_2](https://www.zhihu.com/equation?tex=C_2) 时，模型会生成新的 KV
对，但这一次，由于模型已经读过了问题 ![Q_1](https://www.zhihu.com/equation?tex=Q_1)，它在为
![C_2](https://www.zhihu.com/equation?tex=C_2) 的每个词元生成 KV 对时，会不自觉地将与
![Q_1](https://www.zhihu.com/equation?tex=Q_1) 相关性更高的特征进行强化。

此时生成的 ![C_2](https://www.zhihu.com/equation?tex=C_2) 的 KV
缓存，是一个被问题充分校准过的高质量版本。

于是，当模型最后处理到 ![Q_2](https://www.zhihu.com/equation?tex=Q_2) 时，它会用
![Q_2](https://www.zhihu.com/equation?tex=Q_2) 的查询向量去检索整个序列的 KV 缓存。

此时，缓存中包含了来自 ![C_2](https://www.zhihu.com/equation?tex=C_2)
的高质量信息，使得模型能够轻易地找到并对齐正确的答案。

**所以说复制粘贴其实并没有释放大语言模型的什么潜能，只是通过暴力增加计算冗余，在物理上绕过了因果掩码的限制。**

* * *

那么 CoT 其实也没啥大用，就算不给草稿纸，本身再读一遍其实也没差多少。

而且复读技巧在 Thinking 模型上无效，我怀疑搞不好思考就是复读，复读就是思考。
