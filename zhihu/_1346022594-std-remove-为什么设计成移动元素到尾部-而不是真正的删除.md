title: std::remove 为什么设计成移动元素到尾部，而不是真正的删除？

从一个数组中删除一批元素的最高效的方式就是 std::remove + erase。设想你没有学过 C++，不了解 std
algorithm，那么让你实现删除元素，最可能的写法就是：

    
    
    std::vector<int> nums {1, 2, 3, 4, 5, 6, 7, 8};
    for (auto iter = nums.end() - 1; iter >= nums.begin(); --iter) {
        if (*iter % 2 == 0) {
            nums.erase(iter);
        }
    }
    

可能你还在窃喜自己机智地从后往前遍历了。但是请看一下 erase 方法的复杂度：

> Linear: the number of calls to the destructor of T is the same as the number
> of elements erased, the assignment operator of T is called the number of
> times equal to the number of elements in the vector after the erased
> elements

O(n) * 你自己的循环意味着最终的时间复杂度是 O(n^2)，这很不
scalable。但假设我把要删除的元素一个一个挪到容器后面，同时保持不需要删除元素的相对位置不变，最后直接一波把这些无用元素销毁，复杂度是不是就会低一个数量级？

假设还是从 1,2,3,4,5,6,7,8 中删除偶数，首先将偶数挪到容器后面：

![](https://pic1.zhimg.com/50/v2-48f3ddd7f9f126383924124d15bb4025_720w.jpg?source=2c26e567)

可以发现只需一遍遍历就可以完成元素的移动，然后我再遍历一次将 5 及之后的元素销毁即可。

前面的元素移动恰恰就是 std::remove 所完成的事情，时间复杂度 O(n)；而销毁元素则是 erase 的区间重载，时间复杂度也是
O(n)，两步是前后完成的，所以算法整体的复杂度也是 O(n)。

在其他语言标准库中 std::remove 也被叫做 stablePartition，作用其实就是对数组按条件分区，不一定都是用来移除元素。只不过在 C++
中，[erase-
remove](https://link.zhihu.com/?target=https%3A//en.wikipedia.org/wiki/Erase-
remove_idiom) 是很常用的做法罢了。

至于你问为什么不出一个函数把 std::remove 和 erase 合并起来提供给我们？这里推荐一个视频供你参考：[Embracing
Algorithms](https://link.zhihu.com/?target=https%3A//developer.apple.com/videos/play/wwdc2018/223/)
