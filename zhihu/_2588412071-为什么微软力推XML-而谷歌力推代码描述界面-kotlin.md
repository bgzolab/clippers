各有各的优势。

  * 如果是程序员负责写界面，那么代码描述就拥有无与伦比的优势。
  * 如果是平面设计师负责写界面，那么xml就具备明显优势。

Android为什么往代码描述界面方向转？因为现实中让平面设计师直接写 layout xml 的企业极少，绝大多数安卓开发都还是程序员负责写
layout，那这样的话，layout 单独用 xml 描述就只是缺点不是优点了。

而微软，是制作了很多工具帮助平面设计师的设计图直接生成xml的。也就是说他们确实是希望让平面设计师负责生成xml。自然会更加倾向于xml。

这玩意与 MVVM 其实没有关系，就算
MVVM，也完全可以是界面描述是独立的类，ViewModel是另外一个类，要实现MVC分离并不需要用两种语言，用几个不同的类来组合实现也是一样的。**用两种语言的主要原因还是因为「这是两类不同的人负责去做」**
。如果都是同一个人去写，用两种语言只是麻烦。
