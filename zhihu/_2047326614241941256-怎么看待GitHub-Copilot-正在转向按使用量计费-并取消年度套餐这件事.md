我担心的倒不是 GitHub Copilot 撑不住了，而是 GitHub 似乎快完蛋了。

Copilot 商业模式只是小问题，只需改收费策略止损即可，真正的无底洞是 GitHub Actions。

古法编程时代，大家提交代码都是很谨慎的，基本上会手动分析，确保能过 CI 才会提交。

但在 Agentic Workflow 时代，Agent 的工作逻辑基本上就是 ReAct 盲目试错，试到全绿为止。

AI 根本不懂你那个底层库为什么在 macOS 上能跑，在 Linux 环境下会出 Core Dump。

它没环境，没法解决，所以它就随便改两行代码，强行 Push 进分支，触发 GitHub Actions 去跑测试。

失败了？再改两行，再 Push，再触发。

* * *

根据 6 月 2 日召开的 Microsoft Build 2026 大会披露，2023 年 GitHub Actions 的每周运行分钟数为 5
亿分钟，2025 年增长到每周 10 亿分钟，而 2026 年初就已经飙升到了 21 亿分钟，而且还在指数增长。

然后好事者就去拉了 Kyle Daigle（时任 GitHub COO）的 Commits：

![](https://picx.zhimg.com/50/v2-45883f4f631671127d15cf907b7e164b_720w.jpg?source=2c26e567)

基本上这就是今年 GitHub 上最典型的诈尸曲线了。

全球成千上万个 Agent 毫无节制地拉去 Docker 镜像、下载 Cargo 依赖、编译 Rust 代码，疯狂写入临时文件。

GitHub 的存储系统、索引队列、数据库连接池，全都在承受着 10 倍、100 倍于当初设计的压力。

GitHub 最近半年频繁地出现 502，不爆炸就有鬼了。

这些 AI 提交就像是癌细胞一样疯狂增殖，抢夺正常 PR 的算力与存储，迟早把 Github 这个宿主拖死。

* * *

还有就是 GitHub Trends，现在的榜单上都是些什么妖魔鬼怪。

各种 AI 批量生成的 Skills 提示词包，根本跑不起来的 Vibe 项目，没事干用 Rust 去翻译 C 库的抄袭工程，群魔乱舞。

真正有工程深度，凝聚了人类心血的硬核底层项目，全都被淹没在了 AI 噪音之中。

新的开源项目没法冒头，老牌开源项目也是不胜其扰。

Zig 语言的创始人 Andrew Kelley 早就发飙了，宣布全面禁止任何 AI 生成的代码提交。

Zig 本想培养长期 PR 的蜜蜂，但吸引来的全是一次性 PR 的苍蝇。

* * *

真开源项目（非大厂 KPI 项目）的协作模式类似于师徒制、老带新，通过一些基础的 PR 逐渐培养成熟的 Contributor。

现在好了，全网充斥着为了刷简历、为了让 GitHub 主页变绿的投机客。

这些苍蝇用 Agent 满世界扫开源项目，发现 typo，lint 这种鸡毛蒜皮的小问题就直接让 Agent 生成几十个 PR 批量碰运气求合并。

AI 根本不懂你这个 Rust 模块里为什么要手动 unsafe 控制内存对齐，它只看到 Clippy
报了个警告，就自作主张地把手写的精妙高性能代码替换成了低效的安全操作。

为了证明这个脑残 PR 是错的，维护者还必须逐字逐句去阅读这些没有任何人类思考痕迹的代码，并在脑子里复现整个逻辑，然后用长篇大论去回复对方。

结果回复过去之后，那个提交 PR 的苍蝇连看都不看一眼，直接发给 AI 编造一堆歪理，非要你合并。

他根本就不在乎软件怎么样，他只是刷简历罢了。

* * *

人的精力是有限的，维护者碰到一个两个这种 PR Hacking 的伪人就会受不了，直接关闭所有的外部贡献通道，只接受内部熟人的代码。

这样一来，那种开放包容的开源培养体系就已经彻底完蛋了，新一代参与开源协作的土壤已经不存在了。

* * *

PR Hacking 的伪人只是让开源变得恶心，但是 AI 能做的不止如此，AI 还可以毁灭 Linus’s Law。

开源之所以可以打败闭源，一个原因就是 Linus 认为：

> Given enough eyeballs, all bugs are shallow.  
> 只要有足够多的眼睛，所有的 Bug 都会浮现。

Linus 定律是开源软件能在安全性上抗衡甚至超越商业闭源软件的理论基石。

底层逻辑在于坏人一定是少数，好人一定是多数，只要代码公开，全球无数善良的程序员就会帮着找漏洞、修补丁。

但是在 AI 面前，这条定律不仅失效了，甚至开始反噬。

AI 本身没有善恶，但是恶人有，黑盒还要逆向，白盒分析起来就太简单了。

这些恶意 AI 验证了 Exploit 也不会上报，直接入了黑客的武器库，攻击过程全自动化，几乎零边际成本，一本万利。

* * *

更绝望的是攻防链条极度不对称。

攻击方是完全不用休息的机器，它发现漏洞立刻就能生成攻击载荷，几秒钟就能艹遍全网的开放端口。

而防守方呢，哪怕 AI 同时把漏洞提交给了你，防守依然是一个极其漫长、极其依赖人工共识的物理过程。

你需要人去复现漏洞，你需要讨论怎么修补才不破坏现有架构，你需要发新版本。

最后全球无数使用了你这个开源库的公司还需要人工去升级依赖、跑测试、灰度发布。

只要这根漫长的人类防御链条中有一个环节卡壳，攻击性 AI 就能在那个时间差里，把全世界的目标打成筛子。

* * *

你以为这就完了？

给你推导一下更加黑暗的玩法，全自动供应链投毒。

当年 XZ Utils 后门事件 Jia Tan 花了两年时间，像个老黄牛一样在社区干活，骗取信任，最后埋下后门。

大家惊呼这种社工攻击太可怕了，但是代价也很高，难以复制。

现在呢，恶意组织完全可以租用一千台服务器，部署一万个 AI Agent，给它们设定不同的人设。

数不清的 AI 伪人在 GitHub 上到处游荡，给别人点赞，修一些无足轻重的小 Bug，耐心经营自己的伪人身份和社区信誉。

半年后，它们可能已经混成了几十个底层开源项目的协作者。

然后，在某个设定的时间点，无数恶意 AI 同时发难，在各自的项目里悄悄注入经过高级混淆的后门。

哦吼，整个互联网全部完蛋。

* * *

Github Copilot 收紧只是一个缩影，下一步就是 Github Actions，然后是 Github Packages，Github
Releases，一个个服务逐步腐化，最后完蛋的就是 Github 本身。
