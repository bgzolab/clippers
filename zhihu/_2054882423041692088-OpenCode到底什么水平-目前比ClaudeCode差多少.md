我得先讲一个很反直觉的事实。

Claude Code 很强，这没得争。但它的底层逻辑极其简单粗暴，一个主 agent 配上工具调用，你给它指令，它干活，反馈，再干活。

OpenCode 裸机确实也差不多是这个路子。但一旦你装上 OMO，一切就变了。

我用了小半年，现在长期保留的主 agent 就三个，Sisyphus、Hephaestus 和我自己定义的 Researcher。

Sisyphus 相当于是架构师。你的需求丢给它，它判断任务类型，然后 dispatch 给专门的 agent。Oracle 管架构决策，Librarian
查文档，Explorer 搜代码库，Designer 搞前端 UI，Fixer 修 bug，Observer 监控质量。

而且这些任务可以并行。Sisyphus 可以把三个子 agent 同时撒出去了。Oracle 看架构，Librarian 查文档，Explorer
翻代码，三个任务同时跑，跑完汇总回来，Sisyphus 一句话整合，然后扔给 Hephaestus 去执行。

而且它是真正的异步后台任务系统。子 agent 在独立 tmux 会话里跑，跑完了通过事件通知父
agent。整个过程通过文件做状态追踪，即使会话断了，下次启动接着干。

而且 OpenCode 本身就原生支持很多开源模型，只要 10刀/月的 OpenCode Go 套餐，就能使用 GLM、Qwen、Kimi、DeepSeek
等一大批模型。

我现在的配置，Orchestrator 用 DeepSeek V4 Flash，Oracle 用 V4 Pro，Designer 用 Kimi
K2.7，多模态丢给 Mimo 或者 Qwen Plus。一个月蹬下来完全够用。而 20刀/月的 Claude 套餐去跑 Claude
Code，根本是不够用的。

而且 OpenCode 的 server-client 架构也是一个被严重低估的设计。

一行命令 opencode serve 启动 HTTP server，核心 agent 部分直接变成了一个轻量级的 agent
内核。你可以在上面包任何东西，Chrome 插件、内部工具、自动化流水线，随便玩。我在公司内部做了好几个基于 OC
内核的东西，不说细节根本没人知道底层就是它。

说实话，OpenCode 裸机离 CC
确实有距离。你刚装好不加任何插件直接用，体验会打折扣。但这恰恰是开源设计的必然选择，把核心做成最小可用单元，把上层的最佳实践留给社区插件。OMO、DCP
这些才是真正补完 OC 的东西。
