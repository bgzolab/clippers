是的。

而且Electron一堆bug。

最近我调研了一圈，发现跨平台桌面开发（Win/Mac/Linux），如果不用C++/Qt，最简单的竟然是Java+SWT！这个SWT就是Eclipse开发用的UI框架。

首先它100%封装原生UI，速度极快，虽然外观一般，但非常适合不追求炫酷的桌面应用（实际上很多动画效果屁用没有，自定义风格与系统格格不入）；

![](https://picx.zhimg.com/50/v2-ad2d3bf2457edb9fc8b62b3947ab2731_720w.jpg?source=2c26e567)

其次JDK现在可以裁剪，分发裁剪后的JDK仅30M左右；

最后JDK现在可以做AOT编译。

[SWT | The Eclipse Foundation](https://link.zhihu.com/?target=https%3A//eclipse.dev/eclipse/swt/)

附各种跨平台方案对比：

开发方案| Windows/Mac/Linux 支持| 核心渲染技术| 开发难度| 痛点与门槛  
---|---|---|---|---  
Java + SWT| 完美 / 完美 / 完美| 原生 API 直调| 中等| 需手动管理资源释放（Disposal），布局系统（Layout）较为老旧。  
C# + Avalonia| 完美 / 完美 / 顶级| Skia 自绘| 中等| XAML 有学习成本，但 MVVM 模式对复杂逻辑非常友好。  
Rust + Tauri| 完美 / 完美 / 优秀| 系统 WebView| 高| 必须掌握 Rust 借用检查机制，且需处理 JS 与 Rust
的异步通信。  
Kotlin + Compose| 优秀 / 优秀 / 良好| Skia 自绘| 低| 响应式编程极易上手，声明式 UI 大大减少了代码量。  
C++ + Qt| 完美 / 完美 / 顶级| 混合渲染| 极高| C++ 指针管理、复杂的信号槽机制、庞大的构建系统。  
Flutter (Dart)| 良好 / 良好 / 良好| Impeller 自绘| 极低| “万物皆 Widget”，文档极其丰富，适合快速出原型。  
Electron (JS)| 完美 / 完美 / 完美| Chromium| 极低| 只要会写网页就能上手，唯一的难度是优化性能。  
C# + MAUI| 完美 / 优秀 / 极弱| 原生抽象层| 中等| 跨平台行为不一致时，调试底层 Handler 会让人崩溃。  
  
自绘的最大问题就是看起来和原生总是有怪怪的感觉。
