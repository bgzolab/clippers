看得出来翻译者对大模型已经是十窍通了九窍，把【Token】翻译成【词元】堪比【はちみつ】翻译成【猫】。

官方将 Token 定义为【模型处理信息的最小计量单位】，这本身倒是没啥问题，但是转手就翻译为了【词元】，这就犯了以偏概全的错误。

抛开数学原理不谈，只谈编程表现，Token 是一种抽象的数据单元，在不同的模态下，会有完全不同的物理含义：

  * 在 LLM 里代表子词（Subword），**这个才是词元** 。
  * 在 ViT 里代表图像块（Patch），你可以叫图元。
  * 在 ViViT 里代表时空特征（Tubelet），你可以叫时空元。
  * 在 VLA 里代表状态（State）和动作（Action），你可以叫位元、动元。
  * DNA 也能 Token 化，湍流场也能 Token 化，这些爱叫啥叫啥。
  * 万物即可 Token 化，还有无穷无尽的 X 元家族。

你非要叫词元就会导致后续所有跨模态的讨论都变得极其别扭。

以后的读者只有一个疑问，词在哪？

**如果你支持把词的含义无限外扩，让我们的后代把图片，把声音，把时空，把状态，把动作全部都叫做词，那你确实可以认为 Token 就是词元。**

英文【Token】叠了一大堆不相干的含义，烂的出奇，所以中文【词】也要跟着烂，污染一大堆毫不相干的概念吗？

* * *

严格意义上来讲，Token 的数学定义是高维连续流形向低维离散嵌入进行映射时的离散化索引。

深度学习大模型本质上是一个概率分布预测器，无论是文字、图片、还是视频，在进入Transformer 前都必须经过数值化、离散化。

在数学实现上，一个Token 就是一个整数 ![i \\in \\{0, 1, \\dots,
V-1\\}](https://www.zhihu.com/equation?tex=i+%5Cin+%5C%7B0%2C+1%2C+%5Cdots%2C+V-1%5C%7D)，其中
![V](https://www.zhihu.com/equation?tex=V) 是表空间，它只是一个编号，本身没有任何语义。

这个整数 ![i](https://www.zhihu.com/equation?tex=i) 的唯一作用，是去一个权重矩阵 ![W \\in
\\mathbb{R}^{V \\times
d}](https://www.zhihu.com/equation?tex=W+%5Cin+%5Cmathbb%7BR%7D%5E%7BV+%5Ctimes+d%7D)
中，提取出第 ![i](https://www.zhihu.com/equation?tex=i) 行那个
![d](https://www.zhihu.com/equation?tex=d) 维的向量，这个向量被称为嵌入（Embedding）。

大模型真正在处理的，就这些 ![d](https://www.zhihu.com/equation?tex=d) 维的高维嵌入。

然后官媒的混子专家就像是文盲短视频博主：

  1. 他们不懂大模型的底层数学原理（不知道 はちみつ 日语原意是蜂蜜）
  2. 他们看到大模型在屏幕上吐字（看到 BGM 里配的是小猫）
  3. 他们觉得词元看起来好专业啊，能显得自己很有深度（觉得哈基米配猫很萌，能火）
  4. 原来如此，Token = 词元（好耶！はちみつ = 猫）

这种错误翻译还不如不译。

* * *

这件事上策是启用一个现代汉语中毫无意义的死字，比如【杙】，形式上看起来像是代币、代表。

原意是木桩、锚点，可以理解为在无结构的数据流中打桩，划出一个个可处理的单元。

**甚至可以像化学元素一样，找 unicode 申请一个 【衤 + 弋】读作 tài 或者 táo 的新字。**

中策是保持不译，保留 token 这个专业术语。

下策就是非要找个现存汉语中的词搞语义污染，把一堆毫不相干的东西都叫做【词】。

编一大堆理由，用官方力量推广，摁着头让别人接受。

* * *
