## git 自动补全

用 [https://github.com/git/git/blob/master/contrib/completion/git-
completion.bash](https://link.zhihu.com/?target=https%3A//github.com/git/git/blob/master/contrib/completion/git-
completion.bash) 为 git 添加自动补全，首先下载脚本，（GitHub 可能需要走代理，详见后文）

    
    
    wget https://raw.githubusercontent.com/git/git/master/contrib/completion/git-completion.bash

把下载下来的 git-completion.bash 放到 ~/.bashrc 里 source 一下

    
    
    source git-completion.bash

这时我们可以用 tab 自动补全

![](https://pic3.zhimg.com/v2-4c44504c25d31ee0ce8cf5a1a9419544_1440w.png)git
自动补全

如果你用 zsh，把 Url 改为
[https://raw.githubusercontent.com/git/git/master/contrib/completion/git-
completion.zsh](https://link.zhihu.com/?target=https%3A//raw.githubusercontent.com/git/git/master/contrib/completion/git-
completion.zsh) 就行。

（更新，评论区提醒，新版本的 git 已经自带了completion，在 /usr/share/bash-
completion/completions/git 或者 /etc/bash_completion.d/ 下。我的 Ubuntu-18.04 是在
/usr/share/bash-completion/completions/git）

## 用好 git alias

git 可以配置 alias，比如 `git config --global alias.last 'log -1 HEAD'`，之后我们用`git
last`就相当于`git log -1 HEAD`显示最后一条log。

![](https://pic1.zhimg.com/v2-16314172295848a646467e9c27585992_1440w.png)git
last 查看最近的一条 git log

以下是我的 git alias，可以直接粘贴到你的 ~/.gitconfig 下面。

    
    
    [alias]
            aliases = config --get-regexp alias
            last = log -1 HEAD
            amend = commit --amend --reuse-message=HEAD
            update = fetch --all --prune
            purge = !bash -c \"git branch -r | awk '{print \\$1}' | grep -E -v -f /dev/fd/0 <(git branch -vv | grep origin) | awk '{print \\$1}' | xargs -r git branch -D\"
            graph = log --graph --all --pretty=format:'%Cred%h%Creset - %s %Cgreen(%cr) %C(bold blue)%an%Creset %C(yellow)%d%Creset'
            uncommit = reset --soft HEAD~1
            unstage = reset HEAD --
            stat = diff --stat
    [help]
            autocorrect = 1

这里分享一个我非常喜欢的 git alias 组合，`git update && git purge`。我们在多分支开发，PR 结束的时候，为了让
commit 历史是一条直线，往往会采用 squash commmit，并且删除已经 PR
进去的分支，这时分支在远端分支已经删除了，而本地还保留，如何方便地删除呢？

首先`git update`，这其实相当于`git fetch --all
--prune`，把远端分支和服务器端做同步，删除服务器端不存在的远端分支。这时再`git purge`，如果我们仔细看一下，就明白这是先把有
remote-tracking 的 local 分支找出来，再剔除掉那些还存在远端分支的本地分支，这时剩下的就是曾经 push
过，但远端已经不存在的分支（也就是那些 PR 之后被删掉的分支），然后依次删除。非常安全，不会删除那些还没 push 过的分支。

![](https://pica.zhimg.com/v2-c02d258fa70a591f3760c261673b108e_1440w.png)git
update &amp;amp;amp;&amp;amp;amp; git purge 清理远端不存在的本地分支

## 使用 Windows 下的 git

git-lfs 对于 ssh 的支持不是很好，很多时候我们需要用 HTTPS 协议，而如果在 Windows 上，我们用 git 可以自动使用
Windows credential 而不用输入密码。我们打开的 WSL 终端已经为我们配好了 Windows 下命令的环境变量，只需要用 git.exe
即可，比如 git.exe push 就会使用 git-for-windows 并且不用输入密码。

再进一步，我们想要仅仅在 push/pull/fetch/clone 的时候使用 git.exe，在其他情况下仍然使用 WSL 中的
git，当然可以显式在需要的时候用 git.exe，但如果我们比较懒的话，也可以写一个函数，

    
    
    function git() {
        if [[ "$1" =~ ^(push|pull|update|fetch|clone)$ ]] && [[ -n "$(git config --get remote.origin.url | grep dev.azure.com)" ]]; then
            if [[ "$1" == "update" ]]; then
                git.exe fetch --all --prune
            else
                git.exe "$@"
            fi
        else
            /usr/bin/git "$@"
        fi
    }

上面的 git 函数说，在 Azure DevOps 上，git push/pull/fetch/clone 会用 Windows
上的git.exe，其余情况都用 WSL 中的 /usr/bin/git。

WSL 能方便地调用 win32 的命令行工具，可以玩出很多花样来，比如我们可以写 Makefile 来做项目的构建，一个 Makefile 可以同时支持
Windows 和 Linux （当然存在一些 if/else)。这样 CI 的时候也可以使用同样的 Makefile，本地开发和线上 build
采用同一个脚本，也是非常方便的。

## 让命令行临时走代理

我们在使用 git 或者其他命令行工具的时候，往往速度比较慢，那么如何让命令行走代理加速呢？

首先不推荐通过 export http_proxy 和 https_proxy
环境变量的方式让命令行走代理。因为环境变量影响了所有的命令行工具，而最好在需要的时候能方便地临时连接代理，比如在用公司网络的时候就不需要走代理了。我们可以使用如下的alias，（注意最后有个空格）

    
    
    alias proxy='http_proxy=http://127.0.0.1:1080 https_proxy=http://127.0.0.1:1080 '

之后在需要使用代理的时候，在命令行前加上 proxy 即可，这样可以避免污染环境变量。

    
    
    proxy git clone https://github.com/xxx.git

如果希望 git 总是走代理，也可以修改上面的 git function，比如，

    
    
    function git() {
        http_proxy=http://127.0.0.1:1080 https_proxy=http://127.0.0.1:1080 /usr/bin/git "$@"
    }

注意如果是 WSL2，因为运行在虚拟机里和宿主机通过一个内部交换机链接，所以并不能通过 localhost 访问，这时需要查找 Windows 在 WSL
Switch 下的 ip，并在代理软件勾选“Allow other Devices to connect”，（其实觉得 WSL2 没有 WSL1 方便）。
